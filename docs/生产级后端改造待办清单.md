### [x] 2. 修 `:batch-parse?auto_index=true` 两路执行不一致 — ✅ 已完成（2026-06-05）

- **类型**：Bug 修复（quick win，改动小）
- **风险**：低-中。同一个持久化的 `:batch-parse` 聚合 job，**在 in-process 后台任务里只解析、不构建**（`kb_document_routes.py:4712-4754`），但若该 job 因重启 / `:retry` 被 **durable worker 聚合 executor** 接管，Phase 2 **会真正构建**（`job_worker.py:373-403`）；payload 里已存 `auto_index=true`（`kb_document_routes.py:4653`）却没在 in-process 批量路径兑现。→ "是否构建"取决于谁执行它，行为不等价。
- **要做什么**：让显式 `:batch-parse` 的 in-process 路径与 worker 续跑路径对 `auto_index` 语义一致。两种合法收敛方向，二选一并文档化：
  - (a) in-process 也在 Phase 2 兑现 `auto_index`（与 worker 对齐）；或
  - (b) 显式 `:batch-parse` 明确不支持 `auto_index`（payload 不写、worker 也不构建），并在 API 文档 §3.2 标注 `auto_index` 对 `:batch-parse` 无效（保持它"预留"语义）。
- **验收**：新增回归测试断言同一 `:batch-parse?auto_index=true` job 在"in-process 执行"与"worker 续跑"两条路径下产出一致（要么都构建、要么都不构建）。
- **✅ 实现（2026-06-05）**：选**方向 (b)**——`:parse` / `:batch-parse` 都是 parse-only（route summary 本就写 "without building the index"，且与单文档 `:parse` 现有 no-op 语义一致）。`kb_document_routes.py` 的 batch/single parse route 现把传给 `create_*_parse_plan` / `create_*_parse_job_once` 的 `auto_index` 固定为 `False`，使**持久化 payload 始终 parse-only**；worker 续跑 `_run_aggregate`（仅当 `payload["auto_index"]` 为真才 Phase 2 构建）因此与 in-process 路径一致（都不构建）。`auto_parse` 路径（upload/texts/sync 的聚合 job）不受影响、仍正常构建。两个请求模型的 `auto_index` 字段加注释标注为 reserved no-op。新增回归测试 `test_batch_parse_auto_index_true_stays_parse_only` / `test_single_parse_auto_index_true_stays_parse_only`（断言 job `payload.auto_index is False` 且文档停在 `parsed`）。完整 `tests/api/routes/test_kb_document_routes.py` **74 passed**，ruff 通过。
